# VLAN Tagger

Многопоточный демон для обработки сетевых пакетов с автоматическим добавлением VLAN-тегов на базе конвейерной архитектуры обработки данных.

## Описание проекта

VLAN Tagger представляет собой программный комплекс, реализующий pipeline framework для обработки сетевых пакетов в режиме реального времени. Система перехватывает сетевые пакеты, анализирует их содержимое и добавляет VLAN-теги согласно заданным правилам конфигурации. Архитектура построена на принципах модульности и параллельной обработки данных, что обеспечивает высокую производительность и масштабируемость.

## Функциональные возможности

- Перехват сетевых пакетов через RAW-сокеты на уровне канального уровня
- Динамическое добавление VLAN-тегов (стандарт 802.1Q) на основе IP-адресов назначения
- Параллельная обработка пакетов с использованием многопоточной архитектуры
- Сбор статистики обработки пакетов в режиме реального времени
- Модификация IP-адресов с автоматическим пересчетом контрольных сумм
- Балансировка нагрузки между обработчиками (round-robin, random)
- Централизованное логирование событий системы

## Архитектура системы

Система построена на модульной pipeline-архитектуре, состоящей из следующих компонентов:

### Базовые компоненты

- **Pipeline** - центральный компонент управления конвейером обработки
- **Node** - базовый элемент конвейера с входной очередью и набором выходных подключений
- **Queue** - потокобезопасная очередь для передачи данных между узлами

### Узлы обработки

| Компонент | Назначение |
|-----------|-----------|
| Sniffer | Захват пакетов с сетевого интерфейса |
| Tagger | Добавление VLAN-тегов согласно правилам |
| Sender | Отправка обработанных пакетов в сеть |
| IpModifier | Модификация IP-адресов с пересчетом контрольных сумм |
| PacketCounter | Сбор статистики обработки пакетов |
| Logger | Логирование содержимого пакетов в формате hex dump |
| Dispatcher | Распределение пакетов между воркерами |
| Collector | Агрегация данных из нескольких источников |

### Режимы соединения узлов

**Дублирование данных** (`pipeline_connect`) - каждый узел получает копию всех данных:
```c
pipeline_connect(pipeline, source, destination1);
pipeline_connect(pipeline, source, destination2);
```

**Балансировка нагрузки** (`pipeline_connect_shared`) - данные распределяются между узлами:
```c
Node* workers[] = {worker1, worker2};
pipeline_connect_shared(pipeline, source, workers, 2);
```

## Системные требования

- Операционная система: Linux (kernel 2.6+)
- Компилятор: GCC
- Система сборки: CMake версии 3.25 или выше
- Библиотеки: pthread
- Привилегии: root (для работы с RAW-сокетами)

## Установка и сборка

### Сборка проекта

```bash
mkdir build
cd build
cmake ..
make
```

Результат сборки: исполняемый файл `vlan_tagger`

## Конфигурация

### Файл конфигурации

Создайте файл `vlan-tagger.cfg` в директории сборки:

```
# Формат: IP_START-IP_END-VLAN_ID
0.0.0.0-10.1.0.0-100
10.2.0.0-10.4.255.255-200
192.168.0.0-192.168.255.255-300
```

**Параметры:**
- `IP_START` - начальный IP-адрес диапазона (включительно)
- `IP_END` - конечный IP-адрес диапазона (включительно)
- `VLAN_ID` - идентификатор VLAN (диапазон: 0-4095)

Поддерживаются комментарии (символ `#`) и пустые строки.

### Настройка тестового окружения

Создание виртуальной пары сетевых интерфейсов:

```bash
sudo ./netns_blackhole.sh up
```

Создается:
- Интерфейс `veth0` (10.10.0.1) в основном namespace
- Интерфейс `veth1` (10.10.0.2) в изолированном namespace

Удаление тестового окружения:

```bash
sudo ./netns_blackhole.sh down
```

## Запуск

### Запуск демона

```bash
cd build
sudo ./vlan_tagger <source_interface> <destination_interface>
```

**Параметры:**
- `source_interface` - интерфейс для захвата пакетов (Sniffer)
- `destination_interface` - интерфейс для отправки пакетов (Sender)

Пример:
```bash
sudo ./vlan_tagger veth0 veth1
```

### Остановка демона

```bash
./kill_daemon.sh
```

## Технические детали

### Формат VLAN-тега (802.1Q)

Структура Ethernet-фрейма после добавления VLAN-тега:

```
До обработки:
[MAC destination] [MAC source] [EtherType] [Payload]

После обработки:
[MAC destination] [MAC source] [TPID] [TCI] [EtherType] [Payload]
                                └─ 802.1Q Tag (4 байта) ─┘
```

- **TPID** (Tag Protocol Identifier): `0x8100`
- **TCI** (Tag Control Information): содержит VLAN ID
